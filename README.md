# 딸깍 — 그 사이의 시간

[작품 기획서](docs/딸깍-작품-기획서.md)를 바탕으로 만든 약 68초 시청각 프로토타입입니다. 실제 포트폴리오 소스와 기존 목업 1종, 과정과 결과가 연결되는 가상 샘플 4종을 사용합니다.

## 바로 보기

**GitHub Pages에 배포된 웹사이트를 열거나, 로컬에서 `npm start`를 실행한 뒤 `http://127.0.0.1:5173`을 여세요.** `index.html`은 웹 서버에서 실행하는 진입점입니다.

다른 컴퓨터에 HTML 파일 하나만 전달하려면 `npm run build`로 만든 **[dist/딸깍.html](dist/딸깍.html)**을 사용하세요. 이 파일에는 화면·이미지·코드·음악이 모두 포함됩니다.

첫 화면은 현재 ChatGPT의 어두운 화면을 참고한 대화 UI입니다. 기본 문구 **‘딸깍으로 만들어줘’** 옆의 전송 화살표를 누르거나 Enter를 누르면 소리와 함께 시작합니다. 문구는 직접 바꿀 수도 있습니다.

전송 후 3초 동안 대화의 ‘생각 중’ 표시가 나타납니다. 이어서 같은 응답 영역이 약 0.9초에 걸쳐 브라우저 화면 전체로 확장되고, 작업 과정과 다섯 결과물을 크게 보여줍니다. 마지막 장면이 끝나면 약 0.65초 동안 원래 응답 위치로 축소된 뒤 완료 내용을 표시합니다. 페이지 이동이나 브라우저 창 모드 변경 없이 같은 플레이어를 확대·복귀시킵니다.

관객 화면에는 장면 보기, 작품명·재생 시간 안내, 전시용 인터페이스 안내 링크를 표시하지 않습니다. 제작 검토용 **장면 보기**는 `Alt + Shift + L`, **작품 정보·출처**는 `Alt + Shift + I`로 열 수 있습니다.

- 전송·일시정지·이어보기, 처음부터 다시 재생
- 입력창에서 `Enter` 전송, `Shift + Enter` 줄바꿈; 한글 조합 중 Enter는 전송하지 않음
- 입력창의 정지 버튼으로 일시정지; 응답 안의 재생 버튼으로 이어보기
- 확대된 작품에서 `Space`로 일시정지·재개, `Esc`로 일시정지하며 대화 화면으로 복귀
- `Esc`로 복귀한 뒤 재개하면 응답 안에서 이어지며, 처음부터 다시 재생하면 자동 확대가 다시 적용됨
- 사이드바 **설정**에서 소리 켜기·끄기, 전체 화면
- 배경으로 이동하면 자동 일시정지
- 재생 화면에서 `Space`로 재생·정지, `←` / `→`로 5초 이동 (다른 버튼이나 슬라이더에 포커스가 있을 때는 해당 컨트롤의 기본 키 동작을 따릅니다)
- 크레딧에서 다시 재생하거나 처음 화면으로 복귀

## 실제 자료와 샘플

실제 자료는 `/Users/gonasooc/Desktop/gonasoo.dev/repositories/my_portfolio`의 현재 소스 발췌와 저장소에 있던 `images/mockup/my_mockup.png`입니다. 원본 저장소는 변경하지 않습니다. 목업은 시제품에서 코드와 결과의 연결을 확인하기 위해 선택한 임시 결과이며, 팀의 최종 대표작 선정은 별도입니다.

코드의 나타나는 동작은 현재 소스의 재생 연출입니다. Git 수정 이력이나 실제 코딩 당시의 녹화를 복원한 것이 아닙니다. 과정 화면에서는 작성자 계정이 없는 발췌를 사용합니다.

공간·회화·패션은 이 시제품을 위해 만든 SVG 스터디/완성 이미지 쌍입니다. 음악과 작업음은 Web Audio로 만든 합성 사운드이며 실제 작업 녹음이 아닙니다. 이 구분은 제작 검토용 작품 정보와 `src/resources.js`에서 확인할 수 있습니다. 관객이 보는 완료 응답에는 결과 제목만 표시합니다. 실시간 AI 생성 및 외부 서비스 호출은 없습니다.

코드의 표시와 키보드 소리는 같은 타이핑 스케줄을 사용합니다. 코드가 잠시 멈춰 있는 구간에는 키 소리도 멈춥니다. 음악은 음악 장면에서만 연주하고, 잔향까지 장면 끝 안에 들어오도록 제한합니다. 정지된 포트폴리오 결과에는 키보드 소리를 넣지 않습니다.

플레이어는 재료와 수정의 흔적을 중심으로 구성합니다. 회화는 겹친 안료와 지워진 선, 패션은 인물 없는 청회색 천과 재단선, 공간은 다섯 빛의 면으로 표현합니다. 과정과 결과 이미지가 같은 윤곽을 공유하고, 음악 장면의 선은 실제 재생 음표의 시작과 감쇠에 맞춰 움직입니다. 가상 샘플이라는 구분은 유지합니다.

## 수정과 실행

Node.js 22 이상에서 별도 의존성 설치 없이 실행합니다.

```sh
npm run build
npm test
```

`npm run build`는 별도 전달용 `dist/딸깍.html`을 생성합니다. GitHub Pages 배포에는 이 빌드 결과물이 필요하지 않습니다. 테스트에는 독립 HTML 검사도 포함되므로 위 순서대로 실행하세요.

개발 서버를 사용할 수 있는 환경에서는 다음 명령으로 `http://127.0.0.1:5173`에서 확인할 수 있습니다.

```sh
npm start
```

개발 서버는 원본 JavaScript 모듈을 사용하므로 소스를 수정한 뒤 빌드 없이 새로고침할 수 있습니다.

## GitHub Pages 배포

저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, **main**, **/(root)**를 선택하고 저장합니다. `index.html`, CSS 파일, `src/`, `public/`, `.nojekyll`을 포함한 변경을 `main`에 푸시하면 정적 파일이 배포됩니다. [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

이 저장소의 기본 프로젝트 주소는 `https://gonasooc.github.io/art-hackathon/`입니다. CSS·JavaScript·이미지는 모두 상대경로를 사용하므로 `/art-hackathon/` 아래에서도 로드됩니다. `.nojekyll`은 Jekyll 변환을 생략하고 정적 파일을 그대로 게시하기 위한 파일입니다. `dist/`, `release/`, `.sites/`는 배포에 필요하지 않습니다.

이미지를 교체할 때는 과정과 결과의 한 쌍을 함께 교체합니다. `kind`와 `provenance`, 크레딧도 실제 자료에 맞게 갱신하세요. 자료의 종류가 영상 등으로 바뀌면 해당 장면의 렌더러를 함께 조정해야 합니다. 현재는 자료 업로드 편집기가 아닌 코드 기반 프로토타입입니다.

원본 포트폴리오의 지정된 코드·목업을 다시 추출하려면 원본 경로에 접근할 수 있는 환경에서 실행합니다.

```sh
npm run refresh:portfolio
npm run build
```

## 검증

자동 검사는 장면의 끊김과 다섯 결과물의 순서, 에셋 참조, 원본 코드·이미지 일치, 독립 HTML 패키징, 오디오 시작·정지·이동·재시작·자동 종료를 확인합니다. 원본 경로가 없는 컴퓨터에서는 원본 대조 검사만 건너뜁니다.

샘플을 통한 검증은 연출과 조작 흐름에 대한 것입니다. 실제 다섯 창작자의 작업을 충분히 담는지, 의도한 감상이 관객에게 전달되는지는 실제 자료 선정과 관람 피드백을 통해 확인해야 합니다.
