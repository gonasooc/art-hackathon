# 05 숲 — Blender GLB 직접 로딩

2026-11-07 사용자 제공 `~/Desktop/예술해커톤_영상/숲.glb`를 기준으로 숲 칸을 교체했다. **Blender가 내보낸 실제 메시·재질·텍스처를 Three.js GLTFLoader로 읽는 구조**다. 코드로 원본을 비슷하게 다시 만들지 않는다.

## 로딩 경로

- 웹 모델: `assets/models/forest.glb`
- 로더: `vendor/three/addons/loaders/GLTFLoader.js` (현재 프로젝트의 Three.js 0.187.0)
- 어댑터: `src/carriages/forest-gltf.js`의 `buildForestGLTFCarriage()`
- 통합: `TrainWorld.ensureCar('05')`가 어댑터의 `load()`로 모델 준비를 기다리고 실제 로드된 대상 메시를 `MemoryObjects`에 등록한다. 초기 `world.ready`에는 숲 모델을 포함하지 않는다. 04 카페 진입 때 백그라운드로 준비하고 05 직접 선택·전환 시 미완료라면 로딩 상태에서 기다린다.
- 로딩 실패는 기존 오류 복구 화면으로 처리한다. 코드로 만든 이전 숲으로 조용히 대체하지 않는다.

원본은 Khronos glTF Blender I/O v5.2.41로 내보낸 glTF 2.0이다. 노드 460개, 메시 정의 295개, 재질 39개, 이미지 3개, 애니메이션 0개다. 기본 장면은 `AKL 08 | Mountain Stone Sanctuary`이며 파일 이름과 무관하게 현재 전시의 05 슬롯에 연결한다. 두 번째 기본 Cube 장면은 사용하지 않는다.

## 웹용 사본 준비

원본 파일은 수정하지 않았다. `scripts/prepare-forest-glb.py`가 GLB의 메시·씬 변환을 보존하고 내장 4096px 이미지를 2048px로 줄인다. 음수 텍스처 좌표 인덱스 `texCoord: -1`은 glTF 기본 UV 세트 0으로 정리한다.

- 원본 크기: 87,462,932 bytes (약 83.4 MiB)
- 배포 사본: 21,276,696 bytes (약 20.3 MiB)
- 원본 SHA-256: `44534d4de0472e5488978298a452455f07173376d48756f3c620c67a3fb30b42`
- 객차·바위섬·메인 소멸 대상의 버텍스·인덱스는 유지한다. 반복 배치된 먼 소나무만 `optimize-forest-landscape.mjs`가 원본 메시 기반 저해상도 인덱스로 바꾼다. 총 1,758만 삼각형의 대부분이 이 소나무였으므로 실시간 렌더링을 위한 보정이다.

Pillow가 설치된 Python에서 다음처럼 준비한다. 기본 출력은 `assets/models/forest.glb`다.

```sh
python3 scripts/prepare-forest-glb.py /path/to/숲.glb
node scripts/optimize-forest-landscape.mjs
node scripts/compact-forest-glb.mjs
npm run build
```

`build`는 현재 설치된 Three.js와 동일 버전의 GLTFLoader·BufferGeometryUtils·SkeletonUtils를 복사한다. 정적 서비스에서 별도 import map 없이 사용하기 위해 이 세 파일의 `from 'three'`만 `../../three.module.js`로 바꾼다. 모델과 로더 파일은 해시 매니페스트에 포함한다. 미사용 정점과 폐기된 버퍼는 `compact-forest-glb.mjs`에서 제거한다. 단순화 후 실제 참조되는 정점만 재번호화하므로 표시되는 삼각형·재질·노드 배치는 바뀌지 않는다. 로딩 후 반복 메시 626개는 InstancedMesh로 버퍼를 공유하고, 나머지 정적 메시만 재질별 병합한다. 불필요해진 원본 지오메트리는 dispose한다. 소멸 대상은 별도로 유지한다.

## 전시 좌표와 보행 통합

원본은 긴 방향이 Z축인 객실이다. 루트를 Y축 π/2 회전하고 `[-7, TRAIN.floorY - .13, TRAIN.centerZ]`에 배치해 기존 -X 방향 여정에 맞춘다.

원본 중앙의 큰 바위섬은 보행 통로와 겹친다. 바위섬·계단·분재·이끼·작은 소나무를 한 그룹으로 묶고 원본 X축 폭을 55%로 줄여 X=-1.65에 배치했다. 이 배치 조정은 기존 중앙 통로의 눈높이 경계를 비우기 위한 것이다. 객차 외피·창·물길·바깥 숲·고사리는 원본 구성이다. Blender 원본과 배치가 완전히 같다고 주장하지 않는다.

GLB에는 별도 잔설 메시가 없어 기존 `forest.js`의 `buildForestSnow()`만 보조 객체로 사용한다. 이전 `buildForestCarriage()`는 현재 장면 빌더에서 호출하지 않는다.

| 대상 | 실제 소스 | 응시점 |
| --- | --- | --- |
| `05-moss` | GLB의 `MOSS \| root and rock crack patches` | 관찰 구간에 가까운 실제 삼각형 중심에서 계산. 현재 약 `[-8.0632, 1.66038, -6.80838]` |
| `05-snow` | 기존 잔설·바위 보조 객체 | `[-8.7, 1.62, -9.26]` |
| `05-tree` | GLB의 `MAIN BONSAI \| layered mountain pine` 전체 | `[-10.65, 3.05, -6.3]` |

가져온 이끼·분재는 월드 변환을 보존한 채 소멸 그룹으로 옮기고, 기존 소멸 셰이더와 호환되는 MeshStandardMaterial 계열로 연결한다. 실제 대상 메시로 6m raycast를 수행한다. 대상만 사라지며 바위섬·외피·창밖 식생은 남는다.

## 재질 호환성과 차이

Blender의 모든 노드 셰이더·월드 조명은 GLB에 그대로 포함되지 않는다. 이 파일에서도 일부 재질은 이름만 있고 기본색이 흰색으로 내보내졌다. 텍스처·명시된 색은 유지하며, 텍스처 없는 기본 흰색 나무껍질·황동·숲 지면·바위만 이름에 맞는 색으로 보완했다. UV가 없는 텍스처 메시에는 위치·법선 기반 투영 UV를 생성한다.

소나무 잎의 과도한 흰색 sheen은 끄고 거칠기를 .9로 맞췄다. 유리·수면은 원본 메시와 재질색을 유지하되 transmission을 투명도로 대체해 전체 장면의 추가 렌더 패스를 줄였다. 기존 Three.js 조명·안개·ACES 노출 1.1을 사용한다. 원본 Blender 렌더와 완전히 같은 조명·반사·절차형 재질을 재현한 것은 아니다. 이를 더 맞추려면 Blender에서 관련 재질을 텍스처로 베이크한 GLB가 필요하다.

GLB에는 애니메이션이 없어 현재 새 외부 숲은 정적으로 표시한다. 기존 코드 숲의 자동 배경 나무 이동은 더 이상 사용하지 않는다.

## 확인

`look-compare`로 05 관찰 시점 `[-5.45,2.67,-7.9,-.1865,π/2]`에서 GLB 렌더를 생성해 직접 확인했다. `.cache/forest-glb/first.png`, `restored.png`에 기록했다. 최신 레퍼런스는 이미지가 아닌 실제 GLB이므로 과거 숲 영상과의 밝기 점수를 모델 재현 정확도로 사용하지 않는다.

`forest-gltf.spec.mjs`는 Blender 출처·실제 노드 로딩, 세 대상의 응시·소멸·복원, 통로 좌우 경계에서 전방 충돌을 검사한다. 실제 카메라 정확도·모바일 실기기 메모리·원격 다운로드 속도는 별도 확인 대상이다. 숲 파일은 약 21.3MB이며 첫 화면에서는 요청하지 않는다. 04 카페에서 미리 읽거나 05 선택 시 읽는다. 로딩 중 다른 공간으로 선택을 바꾸면 이전 요청 결과가 화면을 다시 숲으로 돌리지 않는다. 모델은 로드 후 캐시해 재입장 때 재사용한다.

## 성능 최적화 측정

동일 1280×720 Chromium/SwiftShader 관찰 화면, 렌더 20프레임 측정. 전체 기기 RAM·VRAM 측정이 아닌 활성 숲 지오메트리 배열 합계와 브라우저 진단이다.

| 항목 | 최적화 전 | 정점 정리·인스턴싱 후 |
| --- | --- | --- |
| GLB 파일 | 47,419,316 bytes | 21,276,696 bytes |
| 숲 지오메트리 배열 | 1,061,487,108 bytes | 16,120,374 bytes |
| 관찰 렌더 삼각형 | 1,149,696 | 1,149,696 |
| 렌더 호출 | 47 | 65 |
| 20프레임 중앙값 | 674.6ms | 549.6ms |
| 직접 숲 로딩 시간 | 9,299ms | 9,325ms |

버퍼 공유로 렌더 호출은 조금 늘지만 지오메트리 복제가 사라져 메모리 사용이 크게 줄었다. 측정 파일은 `.cache/forest-performance/before.json`, `after-final.json`이다. 이후 지연 로딩도 적용해 첫 화면의 숲 파일 요청이 0회임을 브라우저 검사로 확인한다. 직접 숲을 여는 전체 로딩 시간은 최종 측정에서 줄지 않았다. 초기 화면의 숲 요청을 없앤 것과 메모리 절감이 주된 개선이다. 실기기 FPS·발열은 아직 측정하지 않았으며 SwiftShader 수치를 실제 GPU 성능으로 해석하지 않는다.
