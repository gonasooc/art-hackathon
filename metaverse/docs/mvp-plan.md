# 시선이 데려가는 곳 — MVP 최종 기획

2026-11-06 · 사용자와의 기획 인터뷰 Q1–Q23 및 최종 구현 요청을 반영한 기준 문서.

## 작품의 의도

관객이 별도의 걷기 명령을 내리지 않아도 자연스러운 시선이 가상공간의 경로에 관여하고, 그 경로 끝에서 영상 작품을 만나게 한다. ‘무의식’은 작품의 해석이며 추적기가 판정하는 심리 상태가 아니다. 관객이 규칙을 알아채고 일부러 바라보는 행동도 허용한다.

기존 [기술 검토](../webcam-metaverse-tech-stack.md)는 다인용 아바타·음성·키보드 이동을 전제로 한다. 이번 MVP의 범위와 동작은 이 문서를 우선한다.

## 확정한 체험

입장 → 카메라와 소리 준비 → 시선 보정 → 별도 타깃 검증 → 이동 → 도착 → 시점 정렬 → 소리 있는 영상 한 편 → 종료·다시 체험.

| 인터뷰 | 확정 사항 |
| --- | --- |
| Q1 | 자연스러운 신체 입력을 사용하며 의도·무의식을 분류하지 않는다. 의도적 개입도 허용한다. |
| Q2, Q6 수정 | 유효한 시선이 추적되는 동안 계속 걷는다. 깜빡임 횟수로 전진하는 방식이 아니다. 추적이 끊기면 짧은 유예 후 멈춘다. |
| Q3 | 시선이 만든 경로에 따라 처음 만나는 작품이 달라진다. |
| Q4 | 작품 응시나 클릭이 아니라 지정 영역 도착이 영상의 트리거다. |
| Q5, 추가 확인 | 혼자 노트북 앞에 앉아 경험하는 1인칭 공간이다. |
| Q6 | 눈을 뜬 동안의 시선을 화면 좌표로 추정한다. 키보드·마우스·고개 조향은 제공하지 않는다. |
| Q7 | 폭과 길이가 한정된 직선 통로 끝에 좌우 두 관람 구역을 둔다. |
| Q8 | 한 회차에는 영상 한 편만 관람하고 종료한다. |
| Q9 | 구별되는 짧은 임시 영상 두 편을 만들고 실제 작품으로 교체 가능하게 한다. |
| Q10 | 시선에 따라 카메라가 회전하고, 사용자는 회전한 방향으로 걷는다(B안). |
| Q11 | 공간 입장 전 의도적으로 점을 바라보는 보정을 허용한다. |
| Q12 | 짧은 깜빡임 동안 직전 이동을 잠시 유지한다. 장시간 눈 감음·추적 실패는 정지한다. |
| Q13 | 영상은 공간 안의 큰 스크린에서 재생한다. 주변 공간을 남겨둔다. |
| Q14 | 보정·추적 중단·영상 시간을 제외한 이동은 약 20–40초를 목표로 한다. |
| Q15 | 통로 전방 기준 좌우 약 60도, 상하 약 20도로 회전을 제한한다. 걷기는 바닥 평면이다. |
| Q16 | 화면 중앙을 보면 회전을 멈추고 현재 방향을 유지한다. 가장자리를 볼수록 회전 속도가 증가한다. |
| Q17 | 도착 전 두 구역의 형태·밝기는 동일하다. 제목과 썸네일은 공개하지 않는다. |
| Q18 수정 | 영상에 소리를 포함한다. 음소거를 기본 체험으로 삼지 않는다. |
| Q19 | 첫 지원·검증 환경은 내장 웹캠이 있는 노트북의 데스크톱 Chrome이다. |
| Q20 | 시작·권한·재시작 클릭을 허용한다. 소리 있는 자동재생이 차단되면 재생 버튼으로 복구한다. |
| Q21 | 벽은 보이지 않으며 바닥 경계를 희미하게 표시한다. 경계에서는 바깥 이동 성분만 제거해 전진을 유지한다. 두 도착 구역 사이에 틈을 두지 않고 중앙선은 왼쪽에 포함한다. |
| Q22 | 도착하면 시점을 해당 스크린 정면으로 부드럽게 맞추고 영상 중 이동·회전을 정지한다. |
| Q23 | 보정에 쓰지 않은 타깃으로 검증한다. 충분히 맞지 않으면 입장을 차단하고 재보정한다. 임의 이동·키보드 대체는 없다. |

## 입력과 이동

- 원본 카메라 영상을 기기 내에서 분석하고 눈의 홍채 위치를 눈 모양 기준으로 정규화한다.
- 화면 타깃과 눈 특징의 관계를 회귀 보정한다. 얼굴 좌표 자체를 화면 응시점으로 취급하지 않는다.
- 머리 자세는 조향에 사용하지 않는다. 보정 때와 자세가 크게 달라지면 일시정지하고 자세 복귀·재보정을 안내한다.
- 회전에는 중앙의 작은 무반응 구간, 시간 기반 완화, 속도 제한을 둔다. 유효하지 않은 예측값을 자연스러운 눈 움직임으로 해석하지 않는다.
- 초기 공간은 폭 8m, 시작점부터 도착선까지 18m, 기본 보행 속도 0.9m/s로 설정한다. 수평 회전이 ±60도 이내이므로 정상 추적 중 전방 속도는 0.45–0.9m/s가 된다. 경계에서도 전방 성분을 유지하면 이동 시간은 약 20–40초다.
- 짧은 입력 유예는 초기 250ms로 두며 실제 기기에서 조정한다. 탭 비활성화·창 크기 변경·카메라 종료는 짧은 깜빡임과 별도로 처리한다.
- 창 크기가 달라지면 보정 좌표의 유효성을 다시 확인하기 위해 재보정한다. 숨겨진 탭에서 이동하거나 소리를 재생하지 않는다.

## 화면과 공간

전시장의 정적과 여백을 중심으로 한다. 따뜻한 회백색 바닥과 어두운 주변 공간, 가는 경계선, 동일한 두 스크린을 사용한다. 관객 화면에 게임 조작키·속도계·시선 커서·경로 점수는 표시하지 않는다. 보정 화면에서는 시선 타깃과 진행 상태만 명확하게 보여준다.

입장 화면에는 작품의 짧은 설명, 카메라 사용 목적, 소리 안내, 시작 버튼을 둔다. 추적 실패·재생 차단 등 관객이 해결할 수 있는 상태에는 구체적인 복구 방법을 안내한다.

기존 `line.glb`는 사용자가 제공한 자료로 보존한다. 통로용 모델이 아닌 고밀도 조형물이므로 초기 이동 공간에 자동으로 삽입하지 않는다.

### 후속 요청: 이동 중 미세한 핸드헬드

사용자는 구현 확인 후 ‘이동할 때 화면 앵글이 약간 핸드헬드여야 하되 어지러워서는 안 된다’고 추가 요청했다. 이동 중에만 느리고 연속적인 곡선으로 카메라에 최대 약 0.086도 피치·0.063도 요, 수 mm의 위치 변화를 더한다. 프레임마다 무작위로 튀는 흔들림, 롤 회전, 시야각 변동은 사용하지 않는다. 실제 이동 좌표와 도착 판정에는 영향을 주지 않는다.

정지할 때 빠르게 가라앉히고 영상 중에는 적용하지 않는다. 운영체제의 동작 줄이기 설정에서는 비활성화하며, 관객이 이동 중 ‘흔들림 끄기’로 끌 수도 있다. 작은 진폭은 초기 설계값이며 모든 사람에게 어지럼이 없음을 보장하는 수치는 아니다.

## 데이터와 범위

브라우저에서 시선 추정·3D 렌더링·영상 재생을 수행한다. 원본 영상·눈 이미지·시선 이력은 업로드하거나 영속 저장하지 않는다. 보정 모델은 현재 페이지 메모리에서만 유지하며 종료 시 카메라를 해제한다. 의존성과 모델은 버전을 고정해 정적 파일로 제공한다.

계정, 멀티플레이, 음성 통화, VRM 아바타, 손·신체 조작, 영상 중 깜빡임 효과, 모바일·Safari 최적화는 이번 범위에 포함하지 않는다.

## 구현과 완료 검증

1. 눈 특징 추출, 보정, 독립 검증, 추적 중단을 먼저 구현한다.
2. 시선 기반 회전과 보행, 각도·공간 경계, 좌우 도착 판정을 연결한다.
3. 공간 안 스크린, 시점 정렬, 소리 있는 영상·재생 복구·종료를 연결한다.
4. 보정 실패, 닫힌 눈, 얼굴 이탈, 탭 비활성화, 화면 크기 변경, 카메라 거부, 영상 실패를 검증한다.
5. 기존 ChatGPT 프로젝트의 빌드와 테스트를 유지하면서 `/art-hackathon/metaverse/` 배포 경로를 확인한다.

자동 검사는 이동의 인과관계·도착 시간 범위·경계·상태 전이·보정 게이트·재생과 정적 자산을 검증한다. 합성 입력을 사용한 브라우저 검사는 실제 사람의 추적 정확도를 증명하지 않는다. 별도로 실제 노트북·웹캠에서 보정 후 좌우 시선으로 두 목적지에 도달하는지, 장시간 눈 감음과 얼굴 이탈에서 멈추는지 확인해야 한다. 실측하지 않은 정확도·사용성을 성공했다고 기록하지 않는다.
