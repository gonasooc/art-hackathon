# MVP 검증 기록

검증일: 2026-11-06. 기준은 [최종 기획](mvp-plan.md), 이동 중 핸드헬드, 시선 위치 파티클 표시 요청이다. 최초 MVP와 핸드헬드는 `ab32b5e`로 커밋·푸시됐으며, 아래 시선 표시 추가 검증은 이후의 로컬 변경을 대상으로 한다.

## 실행 환경과 결과

- macOS, Node.js 22.12.0.
- Playwright 1.65.0 / Chromium 158.0.8127.18. 카메라·모델과 WebGL을 브라우저에서 실행.
- `npm run build`: 통과. 기존 ChatGPT 독립 HTML과 메타버스의 고정 정적 자산 준비.
- `npm test`: 74개 통과. 공용 서버 1개, 기존 ChatGPT 59개, 메타버스 14개.
- `npm --prefix metaverse run test:e2e`: 브라우저 시나리오 14개 모두 통과. 시선 표시의 좌표·신호 손실·토글·영상 중 추적·동작 줄이기를 포함한다.
- `git diff --check`: 통과.
- FFprobe: 임시 작품 두 편은 H.264 영상과 AAC 오디오를 포함하는 960×540, 12초 MP4. 첫 영상의 자연 종료와 두 번째 영상의 탐색 후 종료를 확인했다.

## 실제 사용자 확인

이 세션에서 사용자가 자신의 노트북 Chrome으로 로컬 미리보기를 열어 직접 응시 보정을 수행한 뒤, **“입장·시선 이동·영상 재생이 모두 됨”**이라고 확인했다. 이는 실제 카메라 입력이 보정·검증을 통과해 이동과 소리 있는 재생으로 연결됐다는 관찰이다.

이 확인 이후 사용자가 핸드헬드 느낌을 요청했고, 해당 효과를 추가한 뒤 진폭·정지·동작 줄이기를 자동 검증했다. 사용자가 미리보기를 새로고침해 실제로 이동한 뒤 체감 강도를 **“적절하고 불편함 없음”**으로 추가 확인했다. 이는 해당 사용자의 환경에서의 확인이며, 모든 관객에게 편안하다는 보편적 결론이나 다른 기기의 정확도 수치를 주장하지 않는다. 이동 중 끄기와 OS의 동작 줄이기를 제공한다.

## 자동 검사의 범위

전체 흐름 검사 일부는 테스트 전용 네트워크 대체로 `tracker.js`에 합성 눈 특징을 공급한다. 보정·회귀·검증·이동·3D 렌더링·실제 MP4 재생은 구현 코드를 실행하며, 테스트 시간을 줄이기 위해 해당 검사에서만 타깃 시간과 보행 속도를 변경한다. 기본 20–40초 규칙은 별도의 기본 설정 검사에서 확인한다.

테스트용 입력 경로·입장 우회 URL·키보드 조향은 제품에 없다. 실제 모델 검사와 사용자 확인은 합성 입력 검사와 구분한다. 현재 검증은 한 사용자의 환경과 자동 검사 범위이며, 조명·안경·카메라 위치가 다른 여러 관객의 정확도·성능을 측정한 보고서는 아니다.

## 시선 표시 추가 검증의 해석

시선 표시의 중심은 이동에 쓰는 완화 좌표가 아닌 최신 회귀 추정 좌표에 직접 배치한다. 주변 입자는 정확도 범위나 신뢰도 표현이 아닌 장식이다. 표시에는 추가 보간 지연이 없고, 유효한 좌표가 없을 때 임의 위치나 보정 타깃을 대신 그리지 않는다. 화면 프레임 시각과 입력 콜백 시각의 차이로 유효 입력이 순간적으로 사라지던 문제를 발견해 같은 실시간 시계를 기준으로 비교하도록 수정했다.

이 추가 검증은 브라우저의 합성 눈 특징을 이용해 표시 계층을 확인한 것이다. 위의 실제 사용자 확인은 기존 이동·재생·핸드헬드에 대한 확인이며, 파티클 표시 이후의 새로운 사람별 시선 정확도를 측정한 것은 아니다.
