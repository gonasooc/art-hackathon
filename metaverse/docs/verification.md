## 2026-11-07 유년의 집 · 놀이터 · 카페 추가

병원 다음에 02 유년의 집 → 03 놀이터 → 04 카페를 추가하고 기존 숲·임종·향을 05–07로 연결했다. 집의 벽화·천장등·선반, 놀이터의 미끄럼틀 놀이대·그네, 카페의 찻잔·의자·테이블을 기존 메시 응시·깜빡임 소멸에 등록했다. 상세 레퍼런스와 범위는 [구현 기록](childhood-playground-cafe-reference.md)을 따른다. 추가된 놀이터 영상과 01–05 이미지를 반영했으며 집 영상의 좌측 하단 자막은 넣지 않았다.

빌드와 공용·프로젝트 자동 검사 84개, 브라우저 회귀 검사 22개가 통과했다. 8개 칸과 17개 대상의 일반 시선 입력 경로 및 자동 시연 완주, 마지막 연기 글씨, 중간 시연 전환, 재시작, 모든 칸의 소멸·복원, 기존 카메라·보정·핸드헬드·시선 표시를 확인했다. 초기 검사에서 확인한 천장등의 화면 이탈과 놀이터 렌더 지연을 수정했다. 복원 검사는 다음 프레임에 기록되는 상태를 기다리도록 수정했다.

마지막 동선 검토에서 집 뒤쪽 벽을 측면으로 좁혀 출구 통로를 확보했고, 세 칸의 중앙과 양측 이동 경계에서 남은 구조물이 눈높이를 가리지 않는 추가 브라우저 검사 1개도 통과했다. 세 공간의 화면을 직접 검토했고 상·좌·우 추가 캡처도 생성했다. 실제 사람의 시선 추적 성공률은 합성 입력 검사로 단정하지 않는다. 사용자 요청에 따라 여기서 검증을 마무리했다.


## 2026-11-07 중간 전환이 가능한 자동 시연

공개 비주얼 테스트를 수동 공간 선택에서 처음부터 끝까지 이어지는 자동 시연으로 변경했다. 우선 실제 눈 추적을 시도하고, 보정·이동·관찰·칸 전환 또는 오류 복구 화면에서 **자동 시연으로 전환**을 누를 수 있다. 전환은 카메라·워커를 종료하되 현재 이동 상태와 소멸 진행을 초기화하지 않는다. 보정 전에는 기차 앞에서 시작한다. 일시정지·재개는 소멸과 마지막 연기 글씨를 포함한 시연 시간을 함께 멈추며, **처음부터 시연**에서만 초기화한다.

`VisualDemo`는 실제 메시 위 응시점을 순차적으로 바라보고, 충분한 고정 후 양안 깜빡임 표본을 만든다. `TrainJourney`, 실제 메시 raycast, `BlinkInteraction`, 소멸·칸 전환·마지막 장면은 실제 체험과 공유한다. 눈 특징이나 모델 학습 데이터를 주입하거나 보정 통과로 기록하지 않는다. 카메라 샘플은 `eye` 모드에서만 수신한다. 일시정지와 탭 숨김에서는 진행하지 않고, 크기 변경 시 화면 좌표를 다시 투영한다. 기존 수동 개발 점검은 `mode=inspect`로 분리했다.

검증: 빌드와 공용·프로젝트 자동 검사 84개, 자동 시연 브라우저 검사 4개 및 기존 눈 추적 회귀 검사 2개가 통과했다. 카메라 거부 뒤 자동 완주(00–04, 9개 대상의 실제 raycast·깜빡임 순서), 일시정지 중 상태 고정, 중간 크기 변경, 관찰 중 이미 소멸한 의자 유지, 남은 표범만 소멸 후 다음 칸 진행, 리사이즈 복구 후 위치 유지, 재시작 초기화, 일반 시선 체험으로 복귀를 확인했다. 실제 MediaPipe 보정 도중 전환했을 때 카메라 트랙이 모두 종료되는 것도 검증했다. 자동 시연 중 콘솔·셰이더 오류가 없었으며 선택 패널 없는 화면을 직접 검토했다. 브라우저 검사는 이동과 고정 시간을 테스트 안에서만 단축했고 제품 시연은 정상 속도를 사용한다.

## 2026-11-07 향 소멸 후 연기 글씨

Figma `91:746`의 검은 공간·석재 받침·연기로 된 “No click, / one blink.” 문구를 확인하고 마지막 장면을 추가했다. 향·향로의 기존 소멸이 완료된 뒤에만 글씨가 형성된다. 일반 체험은 마지막 장면에서 눈 추적과 보행을 종료하고, 중앙 종료 패널 없이 문구를 유지한다. 비주얼 모드는 같은 장면을 사용하며 복원·반복·일시정지·칸 전환을 지원한다. 동작 줄이기에서는 카메라 이동과 연기 상승 없이 최종 구도와 짧은 페이드로 대체한다.

루트 빌드·자동 검사 84개와 관련 브라우저 검사 3개를 통과했다. 마지막 소멸보다 글씨가 먼저 나오지 않는 조건, 시간 정지, 반복 재생, 초기화, 동작 줄이기, 00부터 04까지의 응시·깜빡임 여정 및 마지막 화면→처음으로 복귀를 검증했다. 콘솔·셰이더 오류가 없고, 형성 중·완성 후 스크린샷을 직접 검토했다. 소스 사진 그대로의 실사 연기가 아니라 입자와 반투명 띠로 구성한 실시간 3D 해석이다.

## 2026-11-07 초기 비주얼 테스트 모드 — 현재는 mode=inspect

카메라·시선 보정 없이 같은 3D 공간과 소멸 효과를 확인하는 별도 `visual` 상태를 추가했다. 시작 화면 버튼과 `?mode=visual&car=02` 같은 주소로 입장하며, 일반 시선 체험의 검증을 통과한 것으로 취급하지 않는다. 기차 앞과 00–04 선택, 카메라 위치 프리셋, 드래그 회전·키보드 이동·높이 조정, 개별/전체 오브젝트 소멸·복원, 밝기 조정·복귀, 애니메이션 정지, 도구 숨김을 제공한다. 종료 시 밝기를 복원하며 포커스/탭을 잃으면 이동 입력을 해제한다. 테스트 중 화면 크기를 바꾸어도 보정을 요구하지 않는다.

실제 Chromium에서 카메라 권한을 강제로 거부한 상태로 전 칸 접근과 9개 대상 소멸·복원을 확인했다. 카메라 요청 0회, 눈 추적 모델/워커 요청 0회, 콘솔·셰이더 오류 0건이다. 숲과 향 칸의 테스트 패널을 포함한 화면도 직접 검토했다. 마우스 회전, 키보드 이동, 관찰 위치 복귀, 초점 상실 시 정지, 밝기와 애니메이션 조정, 도구 숨김, 리사이즈, 일반 체험 복귀 후 카메라 권한 요구 검사를 통과했다. 루트 빌드와 자동 검사 84개도 통과했다.

## 2026-11-07 초기 후속 객차 통합 — 번호 재편 이전

00 자궁은 오브젝트 없이 통과하며, 01 병원 → 02 숲 → 03 병원·임종 → 04 향이 놓인 자리로 연결했다. 숲의 이끼·잔설·나무, 임종 병원의 표범·수의로 완전히 덮인 몸·앤젤링, 마지막 향로와 향을 각각 기존 응시·깜빡임 소멸 시스템에 등록했다. 실제 메시를 맞히는 판정과 보정 성공 기준은 유지했다. 안내 문구는 없으며 공통 윤곽빛만 적용한다. 동작 줄이기에서 응시 대상이 바뀌었을 때도 윤곽 신호가 다시 그려지도록 했다.

Figma 16개 노드와 로컬 숲·임종 병원 영상의 샘플 프레임을 확인했다. 각 객차는 정적 파일만으로 구동되는 절차적 3D이며 새 영상 재생이나 외부 런타임 의존성은 없다. 세 객차의 독립 Chromium 렌더를 검토하고, 모든 대상의 실제 메시 raycast·재질 호환을 확인했다. 숲의 바깥 나무와 향 연기는 동작 줄이기에서 멈춘다. 자궁 밖에서 원래 분홍빛 바깥 공간이 겹치지 않도록 새 객차의 배경을 분리했다.


검증 결과: 루트 빌드와 공용·프로젝트 자동 검사 84개가 통과했다. 기존 브라우저 검사 13개가 통과했고, 최종 통합 흐름 검사도 재실행해 통과했다. 00의 무정지 통과, 01–04의 총 9개 대상에 대한 실제 메시 응시·깜빡임·소멸, 각 출구 이동, 최종 종료를 검증했다. 브라우저 오류와 셰이더 오류는 없었다. 첫 통합 실행의 이전 후광 좌표 및 가속 테스트의 짧은 중간 상태 관측 문제는 테스트를 최종 배치·최종 도착 상태에 맞춰 수정했다. 실제 눈 입력의 성공률이나 어지러움 체감은 이 합성 입력 검사로 확정하지 않는다.

깜빡임/소멸을 설명하는 화면 안내를 제거하고 병원 오브젝트에 은은한 윤곽 신호만 남겼다. 자궁칸의 씨앗을 제거했으며 별도 상호작용 없이 병원으로 이어진다. 빌드, 모듈 검사 24개와 변경된 전체 흐름 브라우저 검사 1개가 통과했다. 응시 범위 확대·선택 유지·접근 감속은 의견으로 제안한 상태이며 아직 판정이나 이동에 적용하지 않았다. 아래의 씨앗 관련 검증은 이전 버전의 기록이다.

## 최신 오브젝트·병원 버전

- 00 씨앗 소멸 후 실제 전진으로 01 병원 진입.

- 영상 DOM 및 재생 없음. 사람 모델 없음.

- 실제 WebGL에서 표면 해체 셰이더와 연기 입자, 병원 렌더링을 확인.
- 브라우저 전체 흐름은 합성 시선과 시간 제어된 깜빡임으로 검증했다. 실제 사용자 깜빡임 성공률은 아직 확인하지 않았다.
- `.cache/verification/hospital-01.png`, `smoke-00.png`에 화면 기록.

## 실제 사용자 확인

이 세션에서 사용자가 자신의 노트북 Chrome으로 로컬 미리보기를 열어 직접 응시 보정을 수행한 뒤, **“입장·시선 이동·영상 재생이 모두 됨”**이라고 확인했다. 이는 실제 카메라 입력이 보정·검증을 통과해 이동과 소리 있는 재생으로 연결됐다는 관찰이다.

이 확인 이후 사용자가 핸드헬드 느낌을 요청했고, 해당 효과를 추가한 뒤 진폭·정지·동작 줄이기를 자동 검증했다. 사용자가 미리보기를 새로고침해 실제로 이동한 뒤 체감 강도를 **“적절하고 불편함 없음”**으로 추가 확인했다. 이는 해당 사용자의 환경에서의 확인이며, 모든 관객에게 편안하다는 보편적 결론이나 다른 기기의 정확도 수치를 주장하지 않는다. 이동 중 끄기와 OS의 동작 줄이기를 제공한다.

## 자동 검사의 범위

전체 흐름 검사 일부는 테스트 전용 네트워크 대체로 `tracker.js`에 합성 눈 특징을 공급한다. 보정·회귀·검증·이동·3D 렌더링·실제 MP4 재생은 구현 코드를 실행하며, 테스트 시간을 줄이기 위해 해당 검사에서만 타깃 시간과 보행 속도를 변경한다. 기본 20–40초 규칙은 별도의 기본 설정 검사에서 확인한다.

기차 여정은 접근 구간과 00칸 내부를 각각 검증하며, 정지·화면 변경처럼 특정 단계에 머물러야 하는 시험은 실제 보행 속도를 사용한다. 동작 줄이기 입자 검사는 신호가 유효한 프레임의 형상을 비교한다. 실제 신호가 오래됐을 때 표시를 숨기는 동작을 애니메이션 오류로 판정하지 않는다.

테스트용 입력 경로·입장 우회 URL·키보드 조향은 제품에 없다. 실제 모델 검사와 사용자 확인은 합성 입력 검사와 구분한다. 현재 검증은 한 사용자의 환경과 자동 검사 범위이며, 조명·안경·카메라 위치가 다른 여러 관객의 정확도·성능을 측정한 보고서는 아니다.

## 시선 표시 추가 검증의 해석

시선 표시의 중심은 이동에 쓰는 완화 좌표가 아닌 최신 회귀 추정 좌표에 직접 배치한다. 주변 입자는 정확도 범위나 신뢰도 표현이 아닌 장식이다. 표시에는 추가 보간 지연이 없고, 유효한 좌표가 없을 때 임의 위치나 보정 타깃을 대신 그리지 않는다. 화면 프레임 시각과 입력 콜백 시각의 차이로 유효 입력이 순간적으로 사라지던 문제를 발견해 같은 실시간 시계를 기준으로 비교하도록 수정했다.

이 추가 검증은 브라우저의 합성 눈 특징을 이용해 표시 계층을 확인한 것이다. 위의 실제 사용자 확인은 기존 이동·재생·핸드헬드에 대한 확인이며, 파티클 표시 이후의 새로운 사람별 시선 정확도를 측정한 것은 아니다.

## 진입 검증 실패 점검

사용자는 ‘시선 위치를 충분히 구분하지 못했어요’라는 메시지로 자주 실패하지만 통과 후 동작은 괜찮다고 보고했다. 코드에서 다음 두 상황을 합성 입력으로 재현했다.

| 입력 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 좌우 추정값 0.37·0.63, 중앙 0.5, 수직 오차 없음 | 중앙 오차 0.15·흔들림 0으로 거리·안정성 기준을 만족하지만 방향 일치가 2/6으로 계산되어 실패 | 실제 조향 함수와 기준을 공유해 방향 일치 6/6, 통과. 같은 좌우 입력으로 각각 약 26.05초에 해당 목적지 도착 |
| 6점 중 한 점만 0.25 오차, 나머지는 정확 | 최대 점 오차 한계를 넘어 전체 보정을 다시 시작 | 한계를 넘은 점은 여전히 실패. 해당 점만 한 번 재측정하고, 신선한 값으로 전체 기준을 다시 평가 |

거리·흔들림 한계를 일괄 완화하지 않았다. 중앙에만 머무는 예측, 잘못된 방향, 지속적인 큰 오차는 계속 차단한다. 부분 재확인에는 원래 모델을 사용하며 검증값을 학습에 재사용하지 않는다. 실패 안내도 방향·위치·흔들림으로 구분한다.

수정 후 사용자에게 같은 로컬 환경에서 다시 진행하도록 요청했고 **‘바로 통과함’**이라는 확인을 받았다. 이는 한 번의 실제 재시도 결과이며 여러 기기에서 실패율을 정량 측정한 결과는 아니다.

### 제공된 콘솔 로그의 의미

- `Sets FaceBlendshapesGraph acceleration to xnnpack by default`: 표정 계수 추론은 기본 XNNPACK 경로로 설정된다. 이 경고만으로 전체 얼굴 추론의 GPU 설정이 실패했다고 볼 수 없다. [MediaPipe 소스](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/cc/vision/face_landmarker/face_landmarker_graph.cc)
- `OpenGL error checking is disabled`: WebAssembly 빌드에서 OpenGL 오류 검사를 생략하는 설정 안내다. GPU가 꺼졌다는 뜻이 아니다. [GL context 소스](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/gpu/gl_context.cc)
- `Created TensorFlow Lite XNNPACK delegate for CPU`: delegate 생성자가 내는 INFO 로그다. [TensorFlow 소스](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/lite/delegates/xnnpack/xnnpack_delegate.cc)
- `Graph successfully started running`: 그래프 시작 성공 메시지다. 보정 통과 여부는 별도의 앱 검증이다.

`[gaze-check]`에는 주 추론 옵션의 실제 선택값(`GPU`/`CPU`), 시도 번호, 통과 여부, 실패 종류, 집계 오차·방향 일치·흔들림·재확인 후보점을 출력한다. 이 중 주 추론 옵션이 GPU여도 표정 서브그래프의 XNNPACK 로그는 함께 나올 수 있다. 원본 영상, 눈 특징 벡터, 실시간 시선 이력은 이 진단에 포함하지 않는다.

## 기차 버전 사용자 확인과 추가 보정

사용자는 기차 앞 → 탑승 → 00칸 이동에 대해 **‘동작 잘 됨’**이라고 확인했다. 다만 진입 검증 실패가 계속되어 다음 진단을 제공했다: GPU 경로, 방향 일치 4/6, 중앙 오차 약 0.241, 최대 오차 약 0.361, 흔들림 약 0.068. 흔들림 기준은 만족했으나 방향과 위치 오차 기준을 넘었다.

이에 첫 학습점 준비 시간 1.8초·이후 정착 시간 0.9초, 촬영 시각 기준 표본 수집, 학습점 내부 교차 검사에 따른 선형·2차 회귀 선택을 추가했다. 9개 학습점에서 하나씩 제외한 예측 오차의 중앙값과 최대값으로 모델을 비교하며, 별도의 6점 검증은 선택이나 학습에 사용하지 않는다. 선형 관계·곡률 관계의 합성 데이터에서 적절한 모델이 선택되고 독립 검증을 통과하는 것을 확인했다.
