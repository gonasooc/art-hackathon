# 시선이 데려가는 곳

**최신 흐름:** 00 자궁(오브젝트 없이 통과) → 01 병원 → 02 유년의 집 → 03 놀이터 → 04 카페 → 05 숲 → 06 병원·임종 → 07 향이 놓인 자리. 영상 관람 대신 메인 오브젝트를 응시하고 깜빡이면 연기처럼 사라집니다. 병원에는 사람 없이 검은 표범과 의자를 배치했습니다. [최신 기획](docs/hospital-object-plan.md)을 우선합니다. 아래 영상 관련 설명은 이전 버전의 기록이며 기존 작품 영상 파일은 재생하지 않으며, 별도 행성 도입 영상만 사용합니다.

행성 도입부를 추가했습니다. 눈 보정 후 제공된 `행성-자궁.mp4`를 무음 재생하고, 마지막 풍경을 현재 3D 공간과 겹쳐 기존 기차 앞 위치로 연결합니다. 도입부에는 시선 입력을 사용하지 않습니다. 처음부터 자동 시연할 때도 재생하며, 체험 도중 자동 시연으로 전환하면 다시 재생하지 않습니다. [도입 연출과 검증 범위](docs/planet-prologue.md).

현재 걷기 속도는 **2.7m/s**로, 1.8m/s와 3.6m/s의 중간값입니다. 실제 시선 체험과 자동 시연에 함께 적용하며, 도입 영상·응시·깜빡임·소멸 연출 시간은 유지합니다.

## 비주얼 테스트 · 자동 시연

기본 체험은 **시선으로 시작**으로 진행한다. 보정이 어렵거나 체험 도중 눈 추적이 불안정하면 우측 하단의 **자동 시연으로 전환**을 누른다. 현재 위치·칸·전환 진행도와 이미 소멸한 오브젝트를 유지하고, 남은 여정을 자동으로 이어간다. 입장 전 보정 또는 카메라 권한에서 막힌 경우에는 기차 앞부터 진행한다.

자동 시연은 정면 이동 → 탑승 → 자궁 통과 → 각 칸의 남은 오브젝트를 하나씩 응시 → 깜빡임 → 소멸 → 다음 칸 → 마지막 연기 글씨까지 진행한다. 실제 체험과 같은 이동·메시 판정·깜빡임·소멸 로직을 사용하지만, 눈 추적의 정확도를 검증하거나 보정을 통과한 것으로 기록하지 않는다. 전환 시 카메라와 워커를 종료하며 추가 권한이나 입력 선택을 요구하지 않는다.

시연 화면에는 **일시정지 / 계속 시연**, **처음부터 시연**, **시연 종료**만 남는다. 세 버튼은 상단의 같은 조작 영역에서 높이·간격·테두리를 공유하며, 좁은 화면에서는 상태 라벨을 숨겨 버튼 공간을 확보한다. 공간·카메라 위치·오브젝트 선택은 필요하지 않다. 화면 크기 변경이나 탭 숨김 동안 진행이 건너뛰지 않으며, 동작 줄이기 설정도 유지한다. **처음부터 시연**을 눌렀을 때에만 진행과 소멸 상태를 초기화한다. 시연 종료 후 처음 화면에서는 다시 실제 시선 체험을 시작할 수 있다.

처음부터 자동 시연이 필요한 경우에는 첫 화면의 보조 버튼 또는 `http://127.0.0.1:5174/art-hackathon/metaverse/?mode=visual`을 사용한다. 이 주소의 이전 `car` 값은 자동 시연 시작 지점을 건너뛰지 않는다.

개발용 수동 공간 점검 도구는 `?mode=inspect&car=07`에 분리되어 있다. 자동 시연 화면에는 표시하지 않으며, 별도의 소멸/복원·자유 카메라 확인을 위한 내부 검증용이다.

웹캠 시선으로 기차에 올라, **00 — 탄생**의 기억을 만나는 1인칭 전시입니다. 최신 공간과 Figma 레퍼런스 적용은 [기차·00칸 기획](docs/train-00-plan.md)을 따릅니다. [기초 기획서](docs/mvp-plan.md)에는 아이트래킹·보정·시선 표시와 핸드헬드의 원래 합의가 남아 있습니다.

## 실행

Node.js 22 이상에서 저장소 루트의 공용 서버를 실행합니다. 실행용 라이브러리·얼굴 모델·영상은 정적 파일로 포함되어 있어 관람에 빌드나 외부 CDN 접속이 필요하지 않습니다.

```sh
npm start
```

- 로컬: `http://127.0.0.1:5173/metaverse/`
- Pages 경로 확인: `http://127.0.0.1:5173/art-hackathon/metaverse/`
- 배포 후: `https://gonasooc.github.io/art-hackathon/metaverse/`

노트북 Chrome에서 **시선으로 시작**을 누르고 카메라를 허용합니다. 얼굴을 화면 정면에 두고 고개를 편하게 고정한 채 점을 눈으로 따라갑니다. 보정 9점과 별도 검증 6점을 통과하면 공간이 열립니다. 공간 안에서는 시선만으로 회전·보행하며, 화면 중앙을 보면 현재 방향을 유지합니다.

처음에는 남색·금색 기차의 열린 문 앞에서 시작합니다. 시선으로 전진해 계단과 문을 통과하면 기차가 출발하고, 00칸 내부로 이어집니다. 00칸은 자궁을 추상화한 살구빛 막과 곡면, 금색 객차 구조로 구성했습니다. 창밖·선로·바퀴·조명의 움직임이 주행감을 만들며, 사용자의 위치를 자동으로 전진시키지는 않습니다. 자궁칸에는 메인 오브젝트가 없으며 그대로 지나 병원으로 이어집니다. 병원에서는 메인 오브젝트가 깜빡임에 반응해 연기처럼 사라집니다. 모든 오브젝트가 사라지면 출구까지 전진해 다음 칸으로 이동합니다. 숲에는 이끼·잔설·나무, 임종 병원에는 검은 표범·수의로 덮인 몸·앤젤링, 마지막 어두운 공간에는 향로와 향이 있습니다. 향이 사라진 뒤에는 출구로 걷는 대신 연기가 “No click, / one blink.”라는 글씨를 이루고 마지막 화면에 머뭅니다. 화면에는 상호작용 설명 대신 은은한 윤곽빛만 표시합니다.

현재 구현한 칸은 **00–07**입니다. 활성 순서는 `JOURNEY_ORDER`에 정의하며, 미구현인 08–14로 진입하지 않습니다. 기차 앞 → 탑승 → 00칸 무정지 통과 → 01–07의 각 오브젝트 소멸 → 마지막 연기 글씨 흐름을 사용합니다.

보정이 통과하지 않으면 얼굴을 밝게 비추고 화면과 자세를 고정해 다시 시도합니다. 일부러 머리를 움직여 조종하거나 키보드로 대신 이동하는 기능은 없습니다. 미세한 핸드헬드는 이동 중 **흔들림 끄기**로 끌 수 있고, OS의 동작 줄이기 설정에서는 적용하지 않습니다.

독립 검증은 실제 이동과 같은 좌우 기준을 사용합니다. 한두 점만 잘못 잡혔을 때는 보정 내용을 유지하고 해당 점만 한 번 재확인합니다. 다시 확인해도 기준에 못 미치면 입장을 막고 재보정을 안내합니다. 콘솔의 `[gaze-check]`에는 방향·위치 오차·흔들림과 주 추론 경로의 집계 진단만 남기며, 눈 이미지나 실시간 시선 이력은 기록하지 않습니다.

보정 첫 점에는 안내를 읽을 준비 시간을 두고, 이후에는 점이 안정된 뒤 촬영된 프레임만 수집합니다. 9개 학습점을 하나씩 제외해 예측하는 교차 검사로 선형·2차 회귀 중 더 안정적인 모델을 고릅니다. 별도의 6점 검증은 모델 선택이나 재학습에 사용하지 않습니다. 진단의 `model`은 선택된 회귀 종류, `trainingCvError`는 학습점 내부의 교차 검사 점수입니다.

보정을 통과하면 이동과 오브젝트 관찰 중 **현재 추정된 시선 위치**에 작은 빛과 입자 무리가 표시됩니다. 중심의 작은 빛이 최신 좌표이고, 주변 입자는 장식입니다. 위치 확인에 지연을 더하지 않으며 마우스나 카메라 앵글로 위치를 대신하지 않습니다. **시선 표시 끄기 / 켜기**로 전환할 수 있습니다. 보정·독립 검증 중에는 정답 타깃에 영향을 주지 않도록 표시하지 않습니다. 눈 감음·추적 실패·오래된 입력에는 중심점을 즉시 없애고 입자만 짧게 사라집니다. 동작 줄이기에서는 입자 형상을 고정하고 시선 좌표만 갱신합니다.

카메라 원본은 로컬 워커에서 분석합니다. 눈 이미지·시선 이력을 업로드하거나 영속 저장하지 않습니다. 오브젝트 관찰 중에도 시선 표시를 이어가기 위해 카메라 추적은 마지막 향 소멸·체험 종료·취소까지 유지하며, 표시 끄기는 카메라 권한 해제가 아닌 시각 표시만 끄는 설정입니다. 도착 후 이동과 회전은 계속 정지 상태입니다. 행성 도입부의 무음 영상 외에 작품 영상·소리는 재생하지 않습니다. 기존 영상 파일은 이전 프로토타입의 자료로만 보존합니다.

## 개발과 검증

이 폴더에서 실행합니다.

```sh
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

`build`는 고정한 의존성에서 배포용 정적 파일을 `vendor/`에 복사하고, 모델·영상의 존재와 해시를 `assets/manifest.json`에 기록합니다. GitHub Pages의 `main` / `/(root)` 배포에는 `vendor/`, `assets/`, `src/`, HTML·CSS가 함께 포함되어야 합니다. 이 프로젝트에는 런타임 서버나 별도 백엔드가 없습니다.

브라우저 검사는 실제 WebGL·MediaPipe 워커·카메라 실패 처리와, 추적기 경계에서 합성 눈 특징을 공급하는 전체 체험 검사를 구분합니다. Google 공개 얼굴 테스트 이미지가 없으면 최초 검사 시 `.cache/fixtures/`에 다운로드합니다. 검사 결과와 실제 사용자 확인은 [검증 기록](docs/verification.md)을 참고하세요. 자동 검사만으로 일반 웹캠의 사람별 정확도를 보장하지 않습니다.

MediaPipe는 얼굴·홍채 랜드마크를 제공하고, 이 프로젝트의 회귀 보정이 화면의 시선 좌표를 추정합니다. 머리 각도를 이동 방향으로 직접 연결하지 않습니다. 정확도는 조명·안경·카메라 위치·자세에 영향을 받으며, 검증 실패·자세 변화에서는 진입을 막거나 이동을 멈춥니다. 검증의 오차 기준은 기기의 실측 결과를 바탕으로 조정할 수 있는 초기값입니다.

## 이전 영상 자료

`assets/films/`에는 이전 시제품의 MP4 파일을 보관합니다. 기존 추상 시청각 샘플은 현재 흐름에서 사용하지 않습니다. 임시 작품은 수학적 애니메이션과 합성음으로 생성했습니다. `ready.mp4`는 같은 비디오 요소의 소리 재생을 준비하는 짧은 무음 파일입니다.

FFmpeg가 설치된 환경에서 재생성할 수 있습니다.

```sh
npm run media
npm run build
```

`line.glb`는 사용자가 제공한 조형물 파일로 그대로 보존했습니다. 통로 모델로 변환하거나 임의로 전시에 삽입하지 않았습니다.
