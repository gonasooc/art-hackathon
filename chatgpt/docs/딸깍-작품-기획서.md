# 《딸깍》 작품 기획서

작성일: 2026-11-05  
기준: 팀 회의 기록과 이후 기획 대화에서 합의한 내용  
현재 단계: 초기 시제품 구현 및 UI 구체화 / 대표작 및 세부 자료 선정 전

최신 UI 방향은 문서 마지막의 **13. UI 구체화**, **14. 발표용 확대·복귀**에 반영했다. 앞선 시작 화면 가안보다 이 방향을 우선한다.

> **딸깍으로 결과를 얻어도, 그 결과에 얽힌 시간과 경험까지 얻는 것은 아니다.**

관객이 한 번 클릭하면, 평소 AI의 결과를 기다리는 시간과 닮은 수십 초 동안 다섯 사람의 작업 기록이 압축되어 나타난다. 쓰고, 지우고, 멈추고, 다시 하는 움직임이 서로 이어진 뒤 각자의 완성작이 차례로 등장한다. 관객은 완성작에서 조금 전 지나간 흔적을 다시 발견한다.

이 문서는 작품의 의도와 합의된 방향을 정리한다. 장면 예시와 시간표는 실제 자료를 선정하면서 구체화할 편집 가안이다.

## 1. 출발점

AI를 활용한 코딩, 작곡, 이미지 제작 등을 두고 사람들은 쉽게 ‘딸깍’이라고 말한다. 이 표현은 결과를 얻기 위한 마지막 조작만 남기고, 그 결과에 얽힌 작업과 선택, 반복과 시간을 시야에서 지워버릴 수 있다.

팀의 대화는 AI가 인간의 축적된 작업을 바탕으로 만들어졌다는 문제의식에서 출발했다. 이후에는 각자가 실제로 가진 자료를 통해, 편리하게 도착한 결과 뒤에 무엇이 있었는지를 드러내는 방향으로 좁혀졌다.

회의에서 특히 중요했던 두 관점은 다음과 같다.

| 관점 | 주목하는 것 |
| --- | --- |
| 보이지 않는 공정 | 누군가는 실제로 거쳤지만, 결과를 받는 사람에게는 보이지 않는 과정 |
| 경험의 부재 | 결과를 얻은 내가 직접 통과하지는 않은 과정 |

두 관점을 연결하는 작품의 중심은 **‘결과를 받는 것’과 ‘그 결과에 얽힌 시간과 경험을 얻는 것’ 사이의 간극**이다.

다섯 사람의 기록은 이 간극을 보여주는 구체적인 재료다. 자기소개나 팀의 성과를 설명하는 것이 목적은 아니다. 각자의 실제 기록에서 출발해, 편리함 뒤에 존재하지만 쉽게 보이지 않는 과정으로 시선을 옮기고자 한다.

## 2. 관객에게 남기고 싶은 경험

관객은 자신이 누른 작은 클릭 하나 뒤에 예상보다 많은 움직임과 시간이 나타나는 상황을 만난다. 과정 중에는 어떤 행위를 알아보기도 하고, 다른 작업으로 전환되면서 놓치기도 한다. 마지막 완성작에서는 앞서 본 조각을 다시 발견한다.

의도하는 변화는 다음과 같다.

- 클릭 전에는 결과가 도착하기를 기다린다.
- 기다리는 동안에는 누군가가 고치고, 멈추고, 다시 시도한 흔적을 마주한다.
- 완성작을 볼 때는 결과 안에 남은 것과, 결과만으로는 알 수 없었던 과정을 함께 떠올린다.

이 반응은 연출의 목표이며 아직 관객에게 검증된 효과는 아니다. 짧은 영상을 보는 것으로 창작자의 수년을 모두 체험했다고 말하지 않는다.

### 작품이 성립하는 기준

- 발표자의 설명을 듣지 않아도 작품 안에서 변화나 어긋남을 경험할 수 있어야 한다.
- 추상화된 화면 속에서도 인간의 구체적인 행위를 잠깐씩 알아볼 수 있어야 한다.
- 과정에서 본 조각과 마지막 완성작 사이에 실제 연결이 있어야 한다.
- 완성작이 등장했을 때 앞에서 지나간 시간을 다시 떠올릴 여지가 있어야 한다.

‘오래 고생했으므로 더 가치 있다’는 평가를 전달하는 것은 목표가 아니다. 작업 시간의 양보다 결과 하나로는 전달되지 않는 선택과 변화에 주목한다.

## 3. 작품의 기본 형식

**관객이 직접 시작하는 시청각 작품**으로 구성한다. 관객 한 사람이 버튼을 누르면 주변 사람들도 함께 관람할 수 있다. 발표 상황에서는 발표자가 같은 버튼을 눌러 시연할 수 있다.

```text
최소한의 시작 화면
        ↓
관객의 한 번의 클릭
        ↓
짧은 대기 표시
        ↓
수십 초 동안 다섯 사람의 작업 기록을 압축해 제시
        ↓
각자의 대표 완성작 다섯 점을 순서대로 공개
        ↓
별도 크레딧
```

### 여기서 ‘기다림’이 뜻하는 것

수십 초는 평소 AI의 응답이나 생성 결과를 기다리는 시간과 닮은 관람 구간이다. 그 안에 팀의 작업 기록과 경험을 압축해서 보여준다.

이 구간을 실제 AI의 내부 처리 과정이나 학습 이력이라고 제시하지 않는다. 실시간 AI 생성은 작품의 필수 조건이 아니다.

다섯 사람의 자료가 특정 모델의 실제 학습 데이터였다는 관계도 확인되지 않았다. 자료는 **다섯 사람의 창작 기록**이라는 위치에서 사용한다.

## 4. 합의한 연출 원칙

### 4.1 과정은 익명으로 혼합한다

과정 중에는 이름이나 직업별로 화면을 나누지 않는다. 개발자 파트, 화가 파트처럼 개별 소개를 이어 붙이는 대신, 서로 다른 작업이 하나의 흐름 안에서 만난다.

손의 움직임, 필체, 연주의 호흡, 수정 방식 같은 개별적인 흔적은 남긴다. 작가 정보는 별도 크레딧에서 제시한다.

### 4.2 자료의 종류보다 행위로 연결한다

편집의 중심은 쓰기, 지우기, 멈추기, 고치기, 다시 하기다. 서로 다른 매체의 동작과 소리가 장면을 이어받는다.

가능한 연결의 예시는 다음과 같다. 실제 사용할 장면은 확보한 자료에 따라 바뀐다.

```text
쓰다가 지워지는 문장
        → 수정되는 코드
        → 같은 자리를 덧칠하는 손
        → 중간에 멈추는 연주
        → 달라진 상태로 돌아오는 문장
        → 다시 시작되는 연주
```

모든 작업을 억지로 같은 동작에 맞추지는 않는다. 각 매체의 차이를 유지하면서 반복과 중단의 리듬으로 연결한다.

### 4.3 처음에는 읽히게, 이후에는 밀도 있게 보여준다

초반에는 하나의 행위와 그 변화가 보일 시간을 준다. 관객이 알아본 조각이 생긴 뒤에 교차 편집, 짧은 겹침, 소리의 잔향을 통해 밀도를 높인다.

압축은 속도만 높이는 방식으로 표현하지 않는다. 같은 조각이 조금 달라진 상태로 돌아오게 하여 반복된 작업의 시간을 드러낸다.

### 4.4 실제 변화의 흔적을 우선한다

공개 가능한 자료 중에서 초안과 최종본, 여러 데모, 수정 전후, 덧칠하는 영상 등 변화가 드러나는 기록을 우선한다.

실패를 반드시 보여줘야 하는 것은 아니다. 선택, 망설임, 반복, 수정이 보이면 된다. 실제로 남아 있지 않은 과정을 과거의 작업 이력처럼 만들어 넣지는 않는다.

### 4.5 추상화하더라도 알아볼 수 있는 조각을 남긴다

자료의 일부를 확대하거나 겹치고 잘라낼 수 있다. 다만 모든 자료가 식별할 수 없는 입자나 질감으로만 바뀌지 않도록 한다.

완성된 그림 전체가 보이지 않아도 같은 자리를 덧칠하는 움직임은 보일 수 있다. 코드 전체를 읽지 못해도 어느 부분이 바뀌는지는 알아볼 수 있다. 이런 구체적인 조각이 작품의 시간감을 지탱한다.

### 4.6 마지막에는 각자의 완성작을 보여준다

다섯 사람의 자료를 하나의 새로운 공동 결과물로 합치는 방향은 채택하지 않았다. 직업과 매체의 차이를 유지한 채 **각자 대표 완성작 한 점, 총 다섯 점**을 순차적으로 보여준다.

과정과 결과를 묶는 장치는 구체적인 조각의 재등장이다. 예를 들어 과정에서 여러 번 들었던 구절이 완성된 음악 안에서 이어지거나, 덧칠하던 부분이 완성된 그림 안에서 발견된다.

앞의 기록은 실제로 해당 완성작과 관계가 있어야 한다. 관계없는 자료를 편집해 특정 작품의 제작 과정처럼 보이게 하지 않는다.

## 5. 장면 구성 가안

과정 구간은 약 30초, 결과물 구간은 약 25~40초를 출발점으로 삼는다. 전체는 약 1분 전후를 예상하되, 실제 자료와 발표 조건에 따라 조정한다. 정확한 길이는 아직 확정하지 않았다.

| 장면 | 시간 가안 | 화면과 소리 | 연출 목적 |
| --- | --- | --- | --- |
| 시작 화면 | 클릭 전 | 버튼과 최소한의 화면 요소 | 작은 행동 하나로 결과가 준비될 것이라는 기대를 만든다. |
| 클릭과 대기 | 클릭 후 약 2초 | 딸깍 소리와 짧은 대기 표시 | 관객의 행동과 작품의 시작을 연결한다. |
| 첫 기록 | 다음 약 7초 | 하나의 작업과 그것을 수정하거나 다시 시도하는 모습 | 이후에 다시 알아볼 구체적인 흔적을 남긴다. |
| 작업들의 교차 | 다음 약 18초 | 매체를 넘나드는 동작과 소리, 달라진 상태로 돌아오는 조각들 | 서로 다른 사람의 시간과 반복을 하나의 리듬으로 경험하게 한다. |
| 과정의 끝 | 다음 약 5초 | 밀도 높은 교차 뒤에 남는 마지막 움직임이나 잔향 | 결과가 등장할 감각적인 간격을 만든다. |
| 다섯 완성작 | 약 25~40초 | 각자의 완성작을 순차 제시하고 앞서 본 조각을 재발견하게 한다. | 결과와 그 앞의 시간을 연결한다. |
| 크레딧 | 미정 | 작가 및 자료 정보 | 작품의 출처를 확인할 수 있게 한다. |

### 완성작을 보여주는 방식

다섯 작품은 같은 화면 구성과 전환 방식을 공유하되, 노출 시간은 매체에 맞춘다. 그림에는 전체를 볼 시간을, 음악에는 앞서 들은 구절을 알아챌 시간을 준다. 글이나 앱도 결과가 읽히는 길이를 확보한다.

작가별 표지나 새로운 인트로를 매번 넣기보다 완성작 자체로 이어간다. 과정과 결과의 관계는 관객이 알아차릴 여지를 두고, 확대 비교나 설명 자막으로 모두 해설하지 않는다.

## 6. 소리의 역할

소리는 장면을 이어 주고 시간의 리듬을 만드는 편집 재료로 사용한다.

- 원본에 남아 있는 작업음과 음악 구절을 활용한다.
- 한 장면의 소리가 다음 장면까지 조금 이어지게 할 수 있다.
- 중단, 침묵, 다시 시작하는 순간도 리듬에 포함한다.
- 음악 작품이 공개되는 구간에는 해당 작품 자체를 들을 공간을 준다.
- 완성작 공개를 별도의 웅장한 상승 음악으로 감싸기보다 앞선 작업의 잔향과 연결한다.

모든 자료에 원본 소리가 있는 것은 아니다. 실제 확보한 영상·녹음·음악을 확인한 뒤 전체 소리 구성을 정한다. 구체적인 음향 장비와 재생 환경도 추후 결정한다.

## 7. 팀의 리소스와 현재 선정 상태

아래는 대화에서 언급된 자료의 종류다. 실제 파일 제출과 최종 사용 선정이 끝났다는 뜻은 아니다.

| 구성원 역할 | 대화에서 언급한 리소스 | 현재 대표 완성작 선정 상태 |
| --- | --- | --- |
| 예술 기획 | 영상, 소스코드, 사진 | 미정 |
| 개발 | 소스코드, 아티클 등 텍스트 자료 | 미정. 포트폴리오 소스코드의 사용만 확정 |
| 공학 공부·인디밴드 활동 | 음악, 소스코드 | 미정 |
| 회화 작업 | 작품 작업 영상, 이미지 | 미정 |
| 아트 디렉션·패션 디자인 | 이미지, 글 | 미정 |

### 현재 확정된 실제 재료

```text
/Users/gonasooc/Desktop/gonasoo.dev/repositories/my_portfolio
```

위 경로의 소스코드를 작품 재료로 사용한다.

현재 확정된 범위는 **소스코드 자체**다. 마지막에 보여줄 포트폴리오 화면, 이미지, 기능 시연, 관련 수정 기록까지 선정된 상태는 아니다. 코드에서 어떤 조각을 가져오고 어떤 결과와 연결할지 추가로 정해야 한다.

현재 파일을 순서대로 드러내는 연출과 실제 수정 이력의 재현은 구분한다. 수정 이력을 사용할 경우에는 실제로 확인 가능한 기록을 기준으로 삼는다.

| 움직임·소리 | 작업 영상이나 연습 녹음이 있다면 사용할 만한 구간 표시 |
| 연결 조각 | 과정과 완성작 양쪽에서 알아볼 수 있는 붓질, 문구, 선율, 화면 동작 등 1개 |

모든 사람이 같은 형식의 자료를 준비할 필요는 없다. 정지 이미지 두 장도 변화의 기록이 될 수 있고, 짧은 데모 두 개도 재시도의 시간을 들려줄 수 있다.

자료 선정은 **대표작 선택 → 관련 과정 기록 선택 → 앞뒤를 연결할 조각 선택** 순서로 진행한다.

## 8. 샘플을 사용하는 첫 시제품의 범위

대표작 선정이 끝나기 전에는 실제 포트폴리오 소스코드와 샘플 리소스를 사용해 화면과 소리의 흐름을 검토한다.

샘플은 다른 구성원의 실제 작업이나 이력을 대신 증언하는 자료가 아니다. 회화·음악·영상·텍스트 등 서로 다른 매체가 연결될 때 연출이 성립하는지 확인하기 위한 가상 재료다.

### 시제품에서 확인할 것

- 한 번의 클릭으로 전체 관람 흐름이 시작되는가.
- 짧은 대기 표시에서 실제 기록의 화면으로 자연스럽게 넘어가는가.
- 초반에는 작업의 행위와 변화가 알아보이는가.
- 서로 다른 자료가 동작과 소리의 리듬으로 이어지는가.
- 과정에서 본 조각을 마지막 결과에서 다시 알아볼 수 있는가.
- 다섯 완성작이 각자의 매체 특성을 유지하면서 하나의 관람 흐름으로 이어지는가.

### 샘플 구성 원칙

- 샘플 과정과 샘플 완성작도 앞뒤가 연결되는 한 묶음으로 만든다.
- 실제 포트폴리오 코드와 가상 샘플을 제작 자료 및 크레딧에서 구분한다.
- 추후 실제 자료로 교체할 수 있도록 자료와 연출 구성을 분리한다.
- 실제 자료를 넣기 전까지는 각 창작자의 경험이 충분히 드러나는지 판단을 유보한다.

시제품의 표현 매체로는 앞서 논의한 버튼 기반 화면을 우선 검토한다. 구체적인 기술 구성은 아직 선정하지 않았다.

## 9. 연출을 검토할 때의 질문

| 발생할 수 있는 문제 | 확인할 질문 | 조정 방향 |
| --- | --- | --- |
| AI의 처리 능력을 과시하는 영상처럼 보임 | 사람의 행위보다 빠른 화면 변화와 정보량만 기억되는가? | 처음 읽히는 행위와 수정된 재시도를 확보한다. |
| 노력의 양을 주장하는 영상처럼 보임 | ‘많이 고생했다’는 설명만 남는가? | 시간의 양보다 선택과 변화가 보이는 기록을 쓴다. |
| 과정이 처음부터 식별되지 않음 | 관객이 알아본 구체적인 조각이 하나라도 있는가? | 초반의 읽을 시간을 늘리고 전환 밀도를 조정한다. |
| 마지막이 다섯 개의 포트폴리오 소개로 끊어짐 | 앞에서 본 과정과 결과를 연결할 수 있는가? | 같은 조각의 재등장과 일관된 전환 방식을 유지한다. |
| 관계없는 자료가 제작 이력으로 읽힘 | 과정 기록이 실제로 해당 완성작과 연결되는가? | 자료 관계를 확인하고 연결되지 않는 기록은 재선정한다. |
| 기다림이 관객을 훈계하는 장치처럼 느껴짐 | 대기 자체를 벌이나 의무처럼 만들고 있는가? | 기다리는 동안 일어나는 구체적인 사건에 집중한다. |

## 13. UI 구체화

초기 시제품 검토 후, 관객이 평소 AI를 사용하는 상황에 더 몰입하도록 ChatGPT의 화면 형식을 채택했다.

- 시작 화면은 실제 ChatGPT의 어두운 화면을 참고해 사이드바, 중앙 입력창, 전송 버튼을 구성한다.
- 기본 입력 문구는 **‘딸깍으로 만들어줘’**다. 문장을 직접 바꾸거나 준비된 문구를 한 번에 전송할 수 있다.
- 전송 후에도 사이드바, 사용자 메시지, 하단 입력창을 유지한다.
- 응답의 로딩 표시 아래에서 기존의 과정 연출을 재생한다. 별도 전시 화면으로 전환하지 않는다.
- 다섯 결과물과 마지막 응답도 같은 대화 영역 안에서 이어진다.
- 관객 화면에서 장면 보기, 작품명·65초 안내, 전시용 인터페이스 안내, 작품 정보 링크 등 몰입을 깨는 부가 UI를 제거한다.
- 재생 시간·장면 번호 같은 검토용 표시도 일반 재생 화면에서 숨긴다. 검토용 장면 이동과 출처 설명은 단축키와 제작 문서로 분리한다.

실제 ChatGPT 서비스에 문장을 전송하거나 AI 생성을 실행하는 것은 아니다. 이 구분과 샘플 자료의 출처는 제작 문서에 기록한다.

## 14. 발표용 확대·복귀

스크린에 띄워 발표할 때 작은 응답 카드가 작품의 가독성을 떨어뜨릴 수 있어, 사용자가 제안한 확대·복귀 연출을 추가한다.

1. ‘딸깍으로 만들어줘’를 전송한다.
2. 대화 화면의 ‘생각 중’을 약 3초 동안 보여준다.
3. 같은 응답 영역이 약 0.9초 동안 화면 전체로 확장되고, 주변 대화 UI는 서서히 사라진다.
4. 기존 과정과 다섯 결과물을 큰 화면으로 재생한다.
5. 마지막 결과를 유지한 채 약 0.65초 동안 원래 응답 위치로 축소한다.
6. 대화 UI와 전송한 문장이 다시 나타나고 완료 응답으로 이어진다.

기존 장면·음악의 상대적인 간격은 보존한다. 현재 시제품의 재생 구간은 67.2초이며 복귀 동작을 포함하면 약 68초다. 자동 확대는 웹 화면 안에서 처리하고, 브라우저의 전체 화면 기능은 발표자가 별도로 사용할 수 있다.

동작 줄이기 환경에서는 화면을 오가는 이동을 생략한다. 재생 중 Esc로 대화 화면에 돌아와 멈출 수 있으며, 처음부터 다시 재생하면 정상 확대 흐름을 다시 시작한다.
